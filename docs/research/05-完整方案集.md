# 企业 Agent 定制 · 完整方案集

**覆盖：组织人员 → 六大核心流程 → 评测质量 → 安全权限 → 数据合规 → 一线推广 → 运维成本 → 路线图。**技术架构沿用已定型的“飞书入口 + 云端 Agent 运行时 + 中央 Skill 工厂”闭环，本方案集回答的是“**人和流程怎么转**”。

## 一、组织与人员协同方案

### 1.1 组织结构(三层)

```
【治理层】AI 治理委员会(客户高层 + 你方负责人,月度)
   —— 自治级别授权、高危清单批准、事故复盘终审(参考 ISO/IEC 42001 管理体系框架)

【你的中央团队】Skill 工厂(6–8 人起步)
   ├─ 平台组(2):Agent 运行时、飞书接入、MCP 工具、基础设施
   ├─ Skill 工厂组(2–3):Skill 产品经理 1 + 行业专家 1–2
   ├─ 评测与质量组(1):评测集、门禁、线上抽检
   └─ 运营组(1–2):遥测分析、失败 case 挖掘、一线支持、推广运营

【客户侧】(每家客户)
   ├─ 业务对接人(中层管理者,成败关键)
   ├─ 关键用户 KU 每部门 1–2 人(种子用户、Skill 共创者、内部答疑人)
   ├─ 领域专家 SME(负责审Skill 内容正确性、接转人工的升级件)
   └─ IT 对接人(系统联通、账号权限)
```

> 中层管理者是 AI 落地成败的第一变量——他们既能推动也能“弱化效果、扭曲方向”，所以客户侧对接人必须选有话语权且受益于该场景的中层，并在方案里给他可见的业务指标([腾讯新闻：成败要看五类中层](https://news.qq.com))。

### 1.2 角色职责与能力画像

| 角色 | 核心职责 | 能力画像 | 起步编制 |
|---|---|---|---|
| Skill 产品经理 | Skill 路线图、需求优先级、版本火车、对客户汇报 | 行业理解 + 产品思维，不需会写代码 | 1 |
| 行业专家(SME) | 把 SOP/经验转成 Skill 草稿、审核内容正确性 | 客户行业 5 年+ 一线经验 | 1–2(可客户出人) |
| Agent 工程师 | 运行时、飞书接入、MCP 工具开发、沙箱与权限 | Python/TS、Claude Agent SDK、MCP | 2 |
| 评测工程师 | 评测集建设、Promptfoo 门禁、模型选型跑分 | LLM 评测方法论、数据分析 | 1 |
| 运营分析师 | 遥测看板、失败 case 挖掘、周报、一线培训 | 数据分析 + 极强的沟通能力 | 1–2 |
| 客户关键用户 KU | 试用反馈、参与 Skill 共创、部门内推广 | 一线骨干、有威信 | 客户出，每部门 1–2 |

**最小可行配置(预算紧张时 3 人)**：1 名全栈 Agent 工程师 + 1 名“行业专家兼 Skill 产品” + 1 名“运营兼评测”，前 8 周可以跑通 M1;质量门禁和审计在 M2 前必须补齐人力。

### 1.3 关键流程 RACI(节选核心三项)

| 流程 | Skill PM | 行业专家 | Agent 工程师 | 评测 | 运营 | 客户 SME | 治理委员会 |
|---|---|---|---|---|---|---|---|
| Skill 生产发布 | **A/R** | R(内容) | C(工具依赖) | R(门禁) | C(遥测输入) | **C** 内容确认 | I |
| 高危操作清单定义 | C | C | C | C | I | **R** | **A** 批准 |
| 事故复盘 | C | C | R(技术) | C | R(报告) | I | **A** 终审 |

### 1.4 协同节奏

- **双周 Skill 版本火车**：需求冻结 → 评测 → 灰度，像发版一样固定节奏，不搞随时改；
- **周会(你的团队)**：看遥测看板过失败 case,决定下周修订项；
- **月度客户联审**：和客户 SME 一起看指标 + 待审 Skill 清单 + 高危操作执行记录；
- **季度治理会**：自治级别调整、扩场景决策。

## 二、六大核心流程方案

### P1 · Skill 生产发布流程(状态机)

```
需求(遥测/客户提出) → 草稿(AI 辅助初稿+专家定稿) → 评测门禁(Promptfoo 阈值)
→ 安全审计(代码/依赖/出口) → 客户 SME 内容确认 → 灰度(1–2 个部门,双周观察)
→ 全量发布 → 运行监控 → (退役/重写)
```

每步有明确准出条件：评测分数低于门禁不进审计；SME 不确认不上线；灰度期负反馈率超标自动回滚。**Skill 需求的最大来源应该是遥测(失败 case),而不是拍脑袋**——运营分析师每周从 trace 里挖需求。

### P2 · 一线使用与三级接管流程(人机协同核心)

**自治级别先分级**(每个场景上线前由治理委员会明确授权，这是 HITL 制度化的关键——借鉴 [code.mil 治理框架](https://code.mil)的"explicit autonomy decisions"):

| 级别 | 行为 | 例 |
|---|---|---|
| L0 建议 | Agent 只给建议，人执行 | 故障诊断建议 |
| L1 确认执行 | Agent 起草，人点卡片确认后执行 | 生成工单、提交申请 |
| L2 自动执行 | Agent 直接执行，事后审计 | 查询类、低风险写入 |

**三级接管:**

```
L1 自治处理:Agent 直接答(L0/L2 场景按授权)
   ↓ 触发接管信号
L2 转人工:会话 + 完整上下文(对话记录/已调工具/参数/结果)打包转
   → 客户值班 SME 在飞书群接手,Agent 降级为助手模式(给资料不动系统)
   ↓ 超出一线 SME 能力
L3 专家升级:升级到行业专家/厂商,处理结果回流
```

**接管触发条件**(客服行业验证过的五类信号):用户明确要求找人；检测到情绪不满；**同一问题第二次尝试失败**；命中高危问题类型(涉钱、涉安全、涉法务)；置信度低或工具调用连续失败。**健康转人工率参考区间 5–10%**([Kommunicate 基准](https://werkon.ai)等来源)——0% 不是好事，说明边界设得太窄没人用，或该转的没转；这个指标要进周报。

**闭环要求(escalate and learn)**:每次接管必须把人工的处理结果回流——SME 的最终答案自动生成“Skill 修订建议”进入 P1 需求池。接管不是流程终点，是 Skill 进化的原料。(这也可以后期自动化：参考 Letta 的 Skill Learning 思路让 Agent 自动起草修订，人只审核。)

### P3 · 高危操作审批流程

高危操作白名单由治理委员会批准(如：大额退款、设备停机、对外承诺)。执行链：Agent 起草 → 飞书审批卡片(带 Agent 的依据摘要)→ 审批人通过(复用客户现有审批习惯)→ 回调 Agent 执行 → 审计留痕。**Agent 永远不进白名单，只做起草人和执行人。**

### P4 · 反馈处理流程

卡片 👍/👎 和“转人工”是两个现成信号源。分级处理 SLA:👎 单次 = 运营 48h 内归因；同 Skill 一周内 👎≥3 或 👎率>10% = 触发紧急修订，插队下一班版本火车；涉安全/合规的错误 = 按 P5 事故流程立即处理。

### P5 · 事故应急流程

三类预案各配 runbook:

| 事故类型 | 响应 | 复盘产出 |
|---|---|---|
| 错误建议造成业务损失 | 立即下线相关 Skill(一键回滚)→ 影响面排查 → 24h 内客户通报 | 修订 Skill + 加评测用例 + 必要时收紧自治级别 |
| 模型/平台故障 | 网关切换备用模型 → 公告 | 模型冗余策略更新 |
| 提示注入/异常行为 | 断开该租户工具权限 → 取证审计 | 权限规则、出口白名单收紧 |

事故分级 P0(造成实际损失/合规事件，治理委员会终审)到 P3(体验问题)，响应时限写入客户 SLA。

### P6 · 模型升级流程

固定四步：新版模型进评测环境 → 全量 Skill 回归(这就是评测集的保险价值)→ 灰度 1–2 周 → 切换或放弃。**基座模型永远锁版本，升级永远走流程**，“底层直接用大模型”的可替换性红利只有靠这条流程才能兑现。

## 三、评测与质量方案

- **评测集三层**：单 Skill 评测集(每 Skill ≥30 条代表性任务，含边界 case)→ 全局回归集(跨 Skill 组合任务 + 历史失败 case 沉淀)→ 红队集(注入、越权、诱导，用 Promptfoo 的红队插件)。
- **门禁阈值示例**(随业务校准)：任务完成率 ≥90%、事实溯源率 100%(答案必须带出处)、高危场景误执行率 = 0、成本/任务 ≤ 预算线。
- **在线质量**：每周随机抽 2% 会话人工评分(运营+客户 SME 交叉)；所有 Skill 变更走 A/B 看无干预完成率。
- **模型选型跑分**：同一评测集跑 Claude/DeepSeek/Qwen/GLM,出分后定模型路线——这是第 4 轮说的“三个拍板问题”之一的决策依据。

## 四、安全与权限方案

**四层权限模型**：飞书身份(谁能用)→ 角色(部门/岗位，来自通讯录)→ 工具白名单(该角色能调哪些 MCP 工具)→ 数据域(工具参数由服务端注入部门/租户 scope,模型无权指定)。**Skill 可见性跟角色走**：财务 Skill 只下发财务部门。

**审计三条铁律**：每次工具调用全量留痕(人/时/参数/结果摘要)；审计库不可变(append-only);高危执行记录保留期 ≥3 年或按行业监管。审计同时服务合规、事故复盘和效果计费三个目的。

**Skill 供应链**：Skill 只从你的中央 registry 分发，不接受终端上传；入库必过代码审计 + 依赖扫描 + 网络出口白名单；生产环境禁用 Bash 与文件写工具(沿用已定架构决策)。

## 五、数据与合规方案

- 数据分级：会话内容默认“客户敏感级”，脱敏后才能进统计仓(手机号/身份证/价格字段规则脱敏)；
- Skill 优化使用客户数据须签数据回流授权条款(种子客户阶段就谈，别到 M3);
- 对外经营路径：调用已备案国产模型 + 完成算法/大模型相关登记，对外前叠齐 ICP/等保/备案“四件套”(详见第 4 轮调研)；若涉境外模型，单独做数据出境评估；
- 治理框架建议对标 ISO/IEC 42001 建立制度文件，客户里的大型企业会要这个。

## 六、一线推广与变革管理方案(采纳决定成败)

1. **共创式启动**：选场景开一线 workshop(零售业验证过的做法)，让 KU 从第一天就参与定义“Agent 该帮我做什么”——采纳率的最大杠杆；
2. **百日打卡式冷启动**：参考国内已验证的全员激励打法——规定次数的使用任务 + 组织排行 + 小额奖励，把“用过”变成习惯([知乎：AI 组织实践](https://zhuanlan.zhihu.com));
3. **培训只教 15 分钟**：三个动作(怎么问、怎么点确认、怎么转人工)，更多靠 Skill 本身的易用性，不做大培训；
4. **答案必须可溯源**：每个结论带出处，这是建立一线信任的第一要素；
5. **中层绑定**：给客户对接中层看部门级指标看板(省时/完成率)，让他的 KPI 和 Agent 效果同向；
6. **组织适配**：长期看按“岗位分层—场景选择—人员分流”路径帮客户做岗位重构设计(省下的时间流向哪)，这是你方案里增值服务的部分，也是打消“AI 抢工作”焦虑的正解；
7. **采纳指标**：周活跃率、人均周会话数、转人工率、NPS 式主观评分，四周爬坡不达标就回炉场景定义，不强推。

## 七、运维与成本方案

- **SLA 建议**(写进客户合同)：消息响应 P95 < 5s、平台可用性 99.5%(M1 阶段降级为尽力而为并明示)、P0 事故 30 分钟响应；
- **监控三层**：基础设施(队列积压/worker 存活)→ 模型层(延迟/限流/错误率，网关自动切换备用模型)→ 业务层(无干预完成率/负反馈率突降告警)；
- **值班**：你的平台组轮值 on-call,客户 SME 值班表对接 P2 流程；
- **成本治理**：单任务 token 成本看板，按租户/部门预算告警；prompt caching 常开(Skill 元数据与系统提示词稳定，缓存命中率高)，这一项通常省 30%+。

## 八、风险登记册(整合更新)

| 风险 | 概率/影响 | 归属方案 |
|---|---|---|
| 中层客户对接人不作为导致采纳失败 | 高/高 | §一1.1 选人标准 + §六6 中层绑定 |
| 模型质量不达标(国产模型工具循环弱) | 中/高 | §三模型跑分 + P6 双模型冗余 |
| 错误建议造成客户实际损失 | 中/高 | P2 自治分级 + P3 审批门 + P5 应急 |
| 转人工率失控(>20% 体验崩 / ~0% 边界过窄) | 中/中 | P2 基准监控 + 周 |
| 数据回流授权缺失中断优化闭环 | 中/高 | §五 种子期签条款 |
| 单点依赖你方少数工程师 | 中/中 | 文档化 + 双人复备 |
| 基座厂商下场做同类行业 Skill | 低/中 | 深耕单行业 + 系统集成深度 |

## 九、实施路线图(人与流程合并视角)

| 阶段 | 产品里程碑 | 人员里程碑 | 流程里程碑 |
|---|---|---|---|
| M1(0–6 周) | 飞书机器人+SDK+5 个 Skill+事件流水 | 3 人核心组就位；招到客户 KU | P2 接管流程人工跑通；P5 最简版 |

**一句话收束**：技术闭环你已经想清楚了，这套方案的核心增量是——**把“Skill 工厂”当成一条有版本火车、有门禁、有值班表的产线来运营，把“人机协同”当成有明确自治分级和接管 SLA 的制度来设计，把“一线采纳”当成有中层绑定和激励机制的变革工程来管理**。三件事都不是技术问题，但任何一件塌了，技术闭环就白建。
