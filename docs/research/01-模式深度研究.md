# 「中央 Skill 工厂 + 一线 Agent 运行时 + 基座大模型」模式深度研究报告

## 一句话结论

**这个模式成立，而且正是 2025 年底到 2026 年业界正在收敛的方向。**你描述的本质是“**技能即服务(Skill-as-a-Service)**”:把行业 know-how 从模型中剥离出来，做成可版本化、可热更新、可审计的技能包；中央团队经营 Skill 的全生命周期(集成→调优→发布)，一线人员只做零门槛消费，模型层直接调用基座大模型、不做微调。它的价值不在模型，而在于**用一套中央工厂的运营体系，把“大模型通用能力”持续转化为“一线可用的行业能力”**。

---

## 1. 模式拆解：你说的四句话对应四层架构

| 你的描述 | 对应架构层 | 核心内容 |
|---|---|---|
| “Agent 能力的定制” | **L3 Skill 层** | 行业能力的原子化封装(SOP、流程、脚本、检查清单) |
| “开放给各行业一线操作人员” | **L4 入口层 + L2 运行时** | IM/语音/手持终端上的 Agent 消费端 |
| “远端做 Skill 的集成调优和升级部署” | **中央 Skill 平台** | 创作、评测、审计、版本管理、灰度发布、遥测回流 |
| “底层直接使用大模型” | **L1 模型层** | 直连基座 API,不微调，模型可随时替换 |

一个直观类比：**基座模型是“通用大学毕业生”，Skill 是“岗位操作手册+工具包”，中央平台是“总部的培训与标准部门”，一线人员是“各门店/产线/工地的员工”。** 总部不断把最佳实践写进手册、下发、回收反馈、修订版本；员工不需要会写手册，只需要会用。

### 与三种既有路线的对比

**对比端到端微调：**微调把 know-how 烧进权重，成本高、迭代以周/月计，且模型一升级就作废。Skill 模式下知识与模型解耦——基座模型升级，Skill 原样可用且自动受益于更强的模型能力。2026 年前沿模型的长上下文和上下文学习能力已经足以让“文档+脚本”替代绝大多数微调场景。

**对比低代码平台让业务部门自建(Coze/Dify/钉钉 AI 助理路线)：**那类平台把开发复杂度推给业务人员，结果是质量不可控、无人调优、大量“搭完没人用”的僵尸 Bot。你的模式反其道而行：**中央专业团队生产，一线零门槛消费**——这是关键差异。

**对比传统 SaaS Copilot:**传统产品把功能写死在版本里，更新靠软件发版。Skill 是热插拔的：今天下发新版故障树，明天全部门店生效，不需要发版。

## 2. 为什么这个模式现在成立(时机论证)

四个基础设施在 2025Q4–2026 相继成熟：

**① Agent Skills 开放标准。**Anthropic 于 2025 年 10 月推出 Agent Skills,12 月开放为 [agentskills.io](https://agentskills.io) 标准，目前已被约 39 个 Agent 平台采纳。格式刻意做得极小：一个文件夹 + 一个 SKILL.md(YAML frontmatter 里 `name` 和 `description`,正文为指令)，可捆绑脚本、参考文档、资源文件。这意味着 Skill 已经是**跨平台的行业事实标准**，你做中央 Skill 工厂不必自创格式。

**② 渐进式披露(Progressive Disclosure)解决了规模化加载问题。**三级加载机制：启动时只把所有 Skill 的 name+description 注入系统提示词 → 命中时才读全文 → 需要时才读捆绑文件。所以一台终端装几百个 Skill 也不会撑爆上下文，且捆绑的脚本可以**不进入上下文直接执行**(比如用 Python 脚本读 PDF 表单字段)，兼顾确定性和 token 效率。

**③ MCP 让工具接入标准化，且治理框架已成熟。**企业通过 MCP 连接 ERP/MES/WMS/CRM,业界已有完整的治理框架：微软、Cloud Security Alliance、GitGuardian 都发布了 MCP 治理最佳实践(OAuth 认证、最小 scope、密钥管理、server registry、防工具投毒)。

**④ 评测基建工业化。**“生产失败 → 沉淀为回归数据集 → CI 门禁拦截质量回退”已是成熟实践(Braintrust、MLflow、Evidently、Langfuse 等工具链)，这正是你“远端调优”模式的技术前提。

宏观面：Gartner 预测到 2026 年底 **40% 的企业应用将内嵌任务型 Agent**(2025 年还不到 5%)。

## 3. 参考架构

### L1 模型层：模型网关 + 直连基座

- 通过统一网关(LiteLLM 类)接入多家基座模型，做路由、降级、成本核算、审计日志。
- **模型可替换是这个模式的最大红利之一**：Skill 与模型解耦后，哪家便宜/强就用哪家，切换时只跑一遍回归评测。
- 国内对外提供服务须用已备案模型(DeepSeek、Qwen、GLM、豆包等，截至 2026 年 8 月已有 1112 款完成备案)；出海或内部使用可接 Claude/GPT/Gemini。

### L2 Agent 运行时

- 核心 agent loop(工具调用 + 代码执行沙箱)，可基于 Claude Agent SDK 或自研。
- 权限模型：RBAC + 按场景白名单 + **高危操作人工确认门**(发货、停机、用药建议等物理世界操作必须留人工闸口)。
- 部署形态按一线环境选：IM Bot(企微/钉钉/飞书)、专用 App/PDA、存量终端改造(POS、工控机、巡检仪)。

### L3 Skill 层(你的核心资产)

建议建立自己的 Skill 分类法，中央工厂按此组织生产：

| 类型 | 内容 | 示例 |
|---|---|---|
| 知识型 | SOP、产品手册、故障树、价格政策 | “冷柜 E4 报警排查树” |
| 流程型 | 多步骤作业指导，带检查点和确认门 | “新品陈列 12 步验收流程” |
| 工具型 | 捆绑脚本做确定性计算/读取 | “耗材用量计算器”“抄表识别脚本” |
| 合规型 | 行业检查清单、话术红线、上报规则 | “金融适当性话术红线” |

每个 Skill 元数据中声明所需 MCP 工具、数据源和权限，运行时据此做权限收敛。**注意一个生产级细节：每个 Skill 的 description 每一轮都会注入上下文，Skill 数量大了之后，description 的触发准确率和长度本身就是中央调优的核心对象。**

### 中央 Skill 平台(“远端工厂”的六个车间)

1. **创作工作台**：行业专家 + Agent 工程师协作；模板库；AI 辅助生成初稿(让模型自己把专家访谈写成 SKILL.md,人审核)。
2. **评测中心**：每个 Skill 强制配评测集(代表性任务 + 评分标准)，作为上线门禁。
3. **安全审计**：捆绑代码人工审查 + 依赖扫描 + 网络出口白名单 + 提示注入检测(官方明确警告：恶意 Skill 可注入指令、外泄数据、触发未授权动作)。
4. **Registry**:语义化版本、依赖解析、多租户分发——技术上类似 npm registry + App Store 审核的合体。
5. **灰度发布**：按门店/产线/病区等组织单元灰度，支持 A/B 和一键回滚。
6. **遥测回流**：任务完成率、转人工率、工具调用成功率、每任务成本、负反馈。

## 4. 中央调优闭环(这个模式的运营心脏)

```
生产 traces → 失败案例挖掘 → 沉淀回归数据集 → 修订 Skill
→ CI 评测门禁 → 按组织单元灰度 → 全量发布 → 遥测监控 → (循环)
```

三个关键设计：

- **Skill 版本升级的三种触发源**：业务变更(SOP 改了)、失败驱动(遥测发现错误模式)、**模型升级**(基座模型一换，全量 Skill 必须重跑回归——这是“底层直接用大模型”必须付出的对价)。
- **北极星指标：一线“无需人工干预完成任务率”**，辅以触发准确率、平均轮次、每任务成本。中央团队的每次调优都要能在这个指标上证明自己。
- **组织配置**：中央团队 ≈ Skill 产品经理 1 + 行业专家 2 + Agent 工程师 2 + 评测工程师 1 + 平台工程师 2(起步 6–8 人可跑一个行业)。

## 5. 一线触达：成败往往在这里而不是模型

**标杆案例验证了入口逻辑：**

- **Lowe's Mylow Companion**(2025 年 5 月)：业界首个大规模门店店员 AI 助手，铺到 **1700+ 门店**，跑在店员销售楼层设备上，语音优先，解决产品查询和新人上手。
- **Walmart**:内部 Copilot "My Assistant" 从 5 万企业员工起步，2025 年升级为完整 Agent 矩阵(Sparky 面向顾客、My Assistant 面向员工、Marty 面向卖家/供应商、Wibey 面向内部运营)，并专门招聘 Agent 编排方向的 Distinguished Architect——说明头部零售已经把“一线 Agent”当成和组织架构同等重要的基础设施。

**一线场景的四条硬设计原则：**

1. **语音优先**——现场作业双手被占用(Lowe's 验证)。
2. **拍照输入**——拍设备铭牌、故障件、现场单据直接进流程。
3. **弱网离线**——skill 包本地缓存，边缘兜底策略(工厂地下室、冷库、工地常态)。
4. **答案可溯源**——每个结论给出处(手册页码、工单号、制度条款)，这是建立一线信任、对抗“AI 瞎说”印象的最有效手段；物理后果越重的场景越必须。

**采纳管理**：KPMG 零售调研反复验证的一点是——让一线从选型期就参与共建(workshop),上线后靠种子用户和师徒激励扩散，而不是行政摊派。

## 6. 安全与合规

**Skill 供应链安全**：只从自家 registry 分发；所有捆绑代码入库前审计；Skill 内指令若要求连接外部网络端点一律拦截；对 MCP server 做 registry 登记和最小 scope。

**一线场景特殊性**：Agent 输出直达物理世界(停机、发货、护理操作)，必须做到操作级人工确认 + 全量审计留痕，这在事故追责时是平台的自保证据。

**国内合规(重要，直接决定你的架构)**：若平台对外(跨企业/面向公众)提供生成式 AI 服务，触发**备案义务**，且要叠满“四件套”——ICP 备案/许可、等保三级、算法备案、大模型备案；2026 年起未备案违规上线**最高可罚 1000 万元**，审核趋严(关键词库建设是高频驳回点)。若只是企业内部员工助手(不面向公众)，门槛低得多，通常走“调用已备案大模型 + 地方登记”即可。**这直接影响选型：对外服务优先接已备案的国产基座模型。**

## 7. 竞争格局与你的差异化定位

| 阵营 | 玩家 | 路线 |
|---|---|---|
| 国际模型厂 | Anthropic(Skills 标准)、Microsoft Copilot Studio、Google Gemini Enterprise | 平台 + 生态，让企业自建 |
| 国际垂类 | Sierra、Glean、Dust | 单场景深做，效果计费 |
| 国内大厂 | 钉钉 AI 助理(入口最强)、企微生态(WorkBuddy 类打通金蝶/用友)、腾讯云 ADP(140+ MCP 插件) | 平台 + IM 入口 |
| 国内开源/低代码 | Coze/扣子(快)、Dify(私有化)、百度秒哒 | 让企业自己搭 |

**共同点：它们都在卖“开发平台”，把最难的行业 know-how 生产留给客户。你的模式是直接经营“技能内容”本身**——卖的不是乐高，是拼好的模型 + 终身保养服务。国内低代码平台搭出来的 Agent 普遍缺乏持续调优，这正是“中央工厂”模式的切入口。

**护城河在哪里(以及不在哪里)：**模型层零护城河；浅层 Skill(通用问答、写周报)会被基座模型升级“吃掉”。真正的护城河是四件事的叠加：①行业私有 know-how 的数据化沉淀(越深越难被通用能力替代)；②业务系统的深度集成(连进 MES/ERP 的 Skill 不可替代)；③使用数据飞轮(遥测→调优→更高完成率)；④行业渠道与信任。**战略含义：切忌一上来铺多行业，先在一个行业做到“系统集成深度 + 数据飞轮”双闭环，再复制。**

## 8. 商业模式(2026 年市场已给出定价锚点)

市场已从“按 token/坐席”转向“按结果”:

| 模式 | 代表 | 价格锚点 |
|---|---|---|
| 按解决结果 | Intercom Fin | $0.99/成功解决 |
| 按解决结果(企业级) | Sierra | 约 $1–2.5/成功解决，企业合同 $35–75 万/年，估值 $158 亿 |
| 按动作消耗 | Salesforce Agentforce Flex Credits | $0.10/标准动作，$500/10万 credits |
| 按坐席 | 传统 SaaS | $29/席/月 量级 |

对你的一线场景，建议三层组合：**平台坐席费(保底)+ 行业 Skill 包订阅(按技能包/年)+ 效果溢价**(在可量化场景，如“维修一次解决率”“巡检覆盖率”上做对赌或分成)。效果计费的前提是遥测体系能客观度量“完成”——这又回到第 4 节的调优闭环，**商业模式和运营体系是同一套基础设施**。

## 9. 主要风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| 基座模型升级导致 Skill 行为漂移 | 高 | 模型版本锁定 + 升级必跑全量回归；Skill 写法向模型无关方向靠 |
| 一线场景幻觉造成物理/合规后果 | 高 | 高危操作人工确认门、答案强制溯源、操作全量留痕 |
| 被基座厂商降维打击(模型厂下场做 Skill 市场) | 中 | 深耕单行业做深集成与数据飞轮，通用能力让给模型 |
| 国内对外服务合规(备案/四件套) | 高 | 架构期即接已备案国产模型；先做企业内部场景过渡 |
| 一线采纳失败(不用/不信任) | 高 | 语音+拍照降低门槛；一线共建；溯源建立信任；盯“无干预完成率”而非激活数 |
| 恶意/劣质 Skill 注入 | 中 | 中央独家分发(不做开放上传)、代码审计、出口白名单 |

## 10. 落地路线图建议

**Phase 0(第 0–4 周)验证价值**：选 1 个行业里“高频 + 有现成 SOP + 容错中等”的场景(设备报修诊断、门店陈列验收、坐席辅助是典型好起点)。直接用基座模型手写 3–5 个 Skill,人工运营，先证明一线愿意用、真能省时间。**这个阶段不要建平台。**

**Phase 1(第 1–3 月)最小工厂**：Git 管理 Skill + 每个技能配评测集 + 简单 registry + 遥测埋点。单客户/单区域试点。

**Phase 2(第 3–6 月)工业化**：灰度发布、安全审计流水线、MCP 接入客户业务系统(连进 ERP/MES 是护城河起点)、“无干预完成率”做到 85% 以上，启动效果计费试点。

**Phase 3(第 6–12 月)复制**：进入第二个行业，目标把“复制成本”压到首个行业的 30%(靠模板、评测框架、平台复用)；探索客户共创 Skill 的市场机制。

选型速记：国内合规版 = 已备案国产模型 + Claude Agent SDK 或自研运行时 + Langfuse 自建评测 + 企微/钉钉入口；国际版 = Claude API + Agent Skills 标准 + MCP + Braintrust。
