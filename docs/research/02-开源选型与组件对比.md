结论先说：**目前没有任何一个开源项目能完整覆盖你这套“中央 Skill 工厂 → 一线运行时”的闭环，但每一层都有成熟的开源组件，组合起来就能搭出 80% 以上**。而且有个好消息：SKILL.md 开放标准已被约 40 个 Agent 支持，你的 Skill 资产天然跨运行时可移植。

## 按四层架构对号入座

| 架构层 | 开源选项 | 成熟度 |
|---|---|---|
| L3 Skill 标准 | [Agent Skills 开放标准](https://agentskills.io)(SKILL.md) | ✅ 事实标准 |
| L2 运行时 | OpenClaw、Letta、OpenHands SDK、Claude Agent SDK | ✅ 原生支持 Skills |
| L2 低代码平台 | Coze Studio、Dify、Bisheng、FastGPT | ✅ 但路线不同(见下) |
| 中央平台：评测门禁 | Promptfoo(CI 红线)+ Langfuse(生产遥测) | ✅ 完备 |
| 中央平台：模型网关 | LiteLLM | ✅ 完备 |
| 中央平台：工具/MCP 注册中心 | MCP Gateway & Registry | ⚠️ 可用但较新 |
| 一线车队级灰度分发、组织树按角色下发 Skill | **无现成开源** | ❌ 需自建(也是你的壁垒) |

## L2 运行时：原生支持 Skill 标准的三个开源 Agent

**[Letta](https://docs.letta.com)(原 MemGPT)— 最值得你关注。**它的 Agent harness 实现了 Agent Skills 开放标准，Skill 可在 Letta、Codex、Claude Code 等之间互通。更关键的是它 2025 年 12 月开创的 **Skill Learning**:Agent 从自己的实战经验中自动把成功做法写成 `.md` 技能文件，人只需中央审核收录——这几乎就是你“远端调优”的自动化形态(经验 → 候选 Skill → 人工审核 → 下发)，而且不改动模型权重。

**[OpenClaw](https://openclaw.ai)(MIT 协议，GitHub 10 万+ star)— IM 入口最现成。**自托管，原生对接 WhatsApp/Telegram 等聊天应用，支持 SKILL.md。做“一线人员在自己聊天工具里用 Agent”的原型验证最快。但要清醒：它是个人助手定位，权限模型宽泛，**直接用于企业一线生产环境安全上不够**，适合拿来做 Demo 和采纳性验证。

**[OpenHands SDK](https://docs.openhands.dev)— 官方支持 AgentSkills 标准**(摘要注入、按需读全文)，工程化程度高，适合嵌入你自己的客户端。

**Claude Agent SDK**:Skill + MCP + 子 Agent 的参考实现，代码开放但绑定 Anthropic 的 API 条款；国内合规场景下可以用它的架构模式自研 harness。

LangGraph、CrewAI、AutoGen 这类属于**编排框架**而非成品 harness,不原生认 SKILL.md,选它们意味着 Skill 层要自己造——与你“Skill 为核心资产”的定位不匹配，不推荐作为底座。

## “平台型”开源(Coze Studio / Dify / Bisheng)为什么不是答案

[Coze Studio 2025 年 7 月开源](https://github.com)后，与 [Dify、FastGPT、Bisheng](https://jimmysong.io) 形成国产开源平台三强/四强。它们能给你多租户、权限、发布通道这些平台骨架，Bisheng 还明确主打企业级“[能力沉淀与数据回流](https://developer.cloud.tencent.com)”。但它们的底层假设是**“让人来平台上搭应用”**，而你的模式是**“中央专业团队生产 Skill、一线零门槛消费”**——消费端根本不该有开发界面。它们可以作为过渡期的管理后台参考，但不是你这个模式的地基。

## 中央平台三层：现成开源拼图

- **评测门禁:[Promptfoo](https://www.promptfoo.dev)** — CLI 优先,YAML 定义测试集,内置 40+ 红队插件(越狱、提示注入、过度授权),直接进 CI 拦截质量回退——这就是“Skill 上线门禁”的现成实现。
- **生产遥测:[Langfuse](https://langfuse.com)** — 开源可自托管,trace/评测/数据集/prompt 管理一体，原生对接 LangGraph、OpenAI Agents SDK、Claude Agent SDK;生产失败 case 一键沉淀为回归数据集,正是调优闭环的数据入口。注意 v3 自托管要 Postgres + ClickHouse,运维不轻;[轻量替代有 Opik、Phoenix](https://genai.qa)。
- **模型网关 + 工具注册:[LiteLLM](https://github.com/BerriAI/litellm)**(多模型路由/预算/审计)+ [MCP Gateway & Registry](https://github.com)(目前唯一把网关+注册中心+安全统一起来的开源项目)。

## 推荐组合

**快速验证版(2 周见原型)**：OpenClaw + 手写 3–5 个 SKILL.md + 现有 IM 通道。只验证“一线愿不愿意用”。

**国内合规生产版**：自研 harness(参考 Claude Agent SDK 模式)或 OpenHands SDK + 已备案国产模型走 LiteLLM 网关 + Promptfoo(CI 门禁)+ Langfuse(遥测)+ Git/OCI 仓库当 Skill registry。入口按行业选企微/钉钉 Bot 或自研 App。

**如果你信“自动沉淀调优”路线**：Letta 做运行时，让 Agent 从实战中自写 Skill 候选，中央团队只做审核与发布——这是目前开源世界里离你“远端持续调优”愿景最近的一块拼图。

## 必须自建的部分(也是护城河所在)

组织树按角色/门店/产线的**灰度下发与回滚**、Skill 与 MCP 工具的**依赖打包**、一线**语音/拍照客户端**、高危操作**确认门**。这些没有开源现成答案——反过来说，这块做出来就是你区别于“又一套 Dify”的产品壁垒。
